Privacy, without vague promises.

The public project site and the locally installed Studio are separate. This notice explains both so a website visit is not confused with running the software.

Public website

The public pages are static files hosted through GitHub Pages. They do not contain a contact form, account system, payment checkout, local Studio API, or portfolio uploader. GitHub may process routine hosting data under its own terms when it serves the pages.

Analytics choice

The tracked site configuration ships with no Google Analytics measurement ID, so no analytics script loads. If a future maintainer configures a valid ID, the site first asks for permission. Choosing “no thanks” keeps the script off. Choosing “allow analytics” stores that choice in your browser and loads Google Analytics with IP anonymisation requested. You can reopen Analytics choices in the footer whenever analytics is configured.

Links and commercial enquiries

Repository, issue, profile, and enquiry links open GitHub. Anything you submit there is handled by GitHub and may be public, depending on the destination. Do not put API keys, portfolio data, personal financial information, or confidential model details in a public issue. There is no claim that clicking an enquiry link creates a contract or sends a private message.

Local Studio

Studio runs on your machine by default. Feed settings are stored under the current user's operating-system configuration directory with restrictive file permissions where the platform supports them. The UI redacts stored header values. A configured credential is sent to the quote URL you select when Studio requests market data; it is not sent to this public website.

Browser storage

The public site may store only the analytics choice described above. Local Studio may store a cached quote in your browser and use a service-worker cache for its own static interface. Clear site data in your browser to remove those browser-side values.

Security and limitations

Studio denies unrecognised Host headers, cross-site browser requests, and state-changing requests without a local session token. Push ingest is disabled unless an operator configures a token or explicitly opts into unauthenticated loopback ingest. No software can promise absolute security; report suspected issues through the repository without posting exploit details or secrets publicly.

Questions or changes

For a privacy question or correction, open a minimal GitHub issue without sensitive information. Material changes to this notice should be visible in repository history.
